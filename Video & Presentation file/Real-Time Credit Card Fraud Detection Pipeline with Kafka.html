The Problem

Catching fraud the moment it happens.

The challenge

Credit card fraud is rare — about 0.17% of transactions — but every second of delay between swipe and detection means more money lost. Batch detection (overnight jobs) is too slow.

The assignment

Build a complete streaming pipeline: read rows from a public dataset, push them through Kafka as live events, run an ML model on every record via a real Streams API, and publish the predictions to an output topic.

Why Kafka

Industry-standard backbone for event streaming. Decouples producers from consumers, scales horizontally, and gives us the buffer we need to apply ML at speed without losing messages.

Why Faust

Python equivalent of Kafka Streams. Lets us define an @app.agent that consumes, transforms, and emits — the official Streams API pattern, no plain consumer loops.

Architecture

Three components, one continuous flow.

1 · Producer
Reads creditcard.csv row by row and publishes JSON to Kafka at ~1 row / second.
raw-transactions
2 · Faust Stream Processor
Loads the trained .joblib model once. An @app.agent scores every incoming event with predict_proba.
fraud-predictions
3 · Output Consumer
Subscribes to predictions and renders a live, color-coded table in the terminal as messages arrive.

Cluster

Confluent Cloud (managed Kafka), SASL_SSL + PLAIN authentication.

Topics

raw-transactions (input) → fraud-predictions (output). 6 partitions, RF=3.

Model

Random Forest classifier wrapped in a scikit-learn Pipeline with StandardScaler.

Dataset

Kaggle Credit Card Fraud — 284,807 transactions.

What's in it

30 numeric features: Time, Amount, and 28 anonymized PCA components V1–V28 (the original features were stripped for confidentiality).

Label: Class = 0 (legit) or 1 (fraud).

The hard part

Severe class imbalance: only 492 fraud rows out of 284,807. That's 0.172%.

Naive accuracy is useless here — predicting "legit" every time still scores 99.83%. We track F1 and ROC-AUC instead, and use class_weight="balanced" when training.

Training pipeline

from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.ensemble import RandomForestClassifier

pipe = Pipeline([
    ("scaler", StandardScaler()),
    ("clf", RandomForestClassifier(
        n_estimators=120,
        max_depth=12,
        class_weight="balanced",
        n_jobs=-1,
        random_state=42,
    )),
])
pipe.fit(X_train, y_train)
# Saved as a single .joblib artifact

Streams API

The Faust agent — the heart of the pipeline.

This is the part the rubric grades for "Streams API usage." No raw consumer loops — every event flows through an @app.agent.

app = faust.App(
    "fraud-detector",
    broker="kafka://<confluent-cloud>",
    broker_credentials=faust.SASLCredentials(...),
    topic_replication_factor=3,
    topic_partitions=6,
)

raw_topic         = app.topic("raw-transactions")
predictions_topic = app.topic("fraud-predictions", value_type=Prediction)

# Load the trained model exactly once, at process start
MODEL = joblib.load(MODEL_PATH)["pipeline"]

@app.agent(raw_topic)                              # <-- THE STREAMS API
async def process(stream):
    async for raw in stream:                       # consume
        payload = json.loads(raw)
        proba   = float(MODEL.predict_proba(vectorise(payload))[0, 1])    # predict
        await predictions_topic.send(value=Prediction(...))         # produce

What to look for

Reading the live output.

  • FLAG column — OK for legit predictions, FRAUD when p ≥ 0.5.
  • P(FRAUD) — the model's probability that this transaction is fraudulent.
  • ACTUAL — ground-truth label that travelled along with the event. 0(OK) means the model agreed, 1(MISS) means it disagreed.
  • Rolling summary — every 25 messages, the consumer prints processed count and flag rate.

What proves the pipeline works

Three things, visible at the same time:

① Terminal 3 is sending rows.

② Terminal 2's [stream] lines appear within ~1 second of each producer send.

③ Terminal 1's predictions arrive in real time with the correct ML score on every row.

That's the full pipeline: source → Kafka → Streams ML → sink.
